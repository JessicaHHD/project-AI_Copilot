# 新人价自动化工具 Full PRD

文档版本：2026-08-09  
产品阶段：本地半自动工具 + GUI MVP。  
目标读者：产品评审、业务运营、研发协作者、作品集面试官。  
优先级说明：当前优先支撑 AI 产品经理作品集 Demo，不以生产级长期平台为首要目标。

## 1. 产品概述

新人价自动化工具用于帮助运营完成新人价批次提报闭环，覆盖从大盘源表筛品、查价、业务确认、后台提报到审核结果整理回填的完整链路。当前产品形态是“命令行主流程 + 批次看板 GUI + 只读 API/React 工作台壳”。

产品不是全自动替代运营，而是把规则明确、重复性高、文件处理复杂的动作交给工具，把业务确认、真实提报、审核导出等高风险动作保留给人工确认。

## 2. 背景

### 2.1 业务背景

新人价提报需要在多个系统与文件之间切换：订单源表、后台查价、Outlook 邮件、查价结果 Excel、业务确认表、提报 PART 文件、后台报名页面、审核导出文件和最终回填表。每个批次都存在大量重复操作和文件判断。

### 2.2 项目现状

- CLI 主流程已经覆盖筛品、拆分、查价、Outlook 下载、查价整合、新人价计算、提报文件生成、后台提报、审核导出、提报情况整理回填。
- 工作流向导已串联关键阶段，并写入批次清单。
- Streamlit GUI MVP 已可展示批次看板。
- FastAPI + React 工作台壳已可读取看板数据并展示更接近产品化的界面。
- `run.bat` 和 `run_test.bat` 仍是完整流程的主入口。

## 3. 目标与非目标

### 3.1 产品目标

- 帮助运营用批次视角理解当前进度、下一步动作和关键产物。
- 降低人工找文件、改名、复制、整理和回填的成本。
- 降低误上传历史文件、误整合错误查价结果、误触真实提报的风险。
- 支撑作品集 Demo，用产品化方式呈现脚本自动化价值。
- 为后续服务化接口和平台化工作台留下清晰边界。

### 3.2 当前非目标

- 不修改新人价筛选规则。
- 不修改查价逻辑。
- 不修改 Outlook 下载逻辑。
- 不修改后台提报逻辑。
- 不改 `main.py` 现有工作流。
- 不把真实提报、审核导出、自动发邮件做成 GUI 按钮。
- 不做多用户权限、任务调度、云端部署、生产级审计。

## 4. 用户与场景

### 4.1 用户角色

| 角色 | 核心任务 | 成功标准 |
| --- | --- | --- |
| 一线运营 | 完成一批新人价提报 | 能按阶段完成查价、确认、提报、回填 |
| 运营负责人 | 了解批次效率和失败原因 | 能查看提报状态、异常和复提机会 |
| 业务协同方 | 确认是否参与报名 | 能收到清晰确认表并反馈结果 |
| Demo 评审者 | 判断产品化能力 | 能看懂痛点、MVP 取舍和后续演进 |

### 4.2 核心场景

1. 首次提报：有新的大盘源表，工具筛选候选 SKU 并走查价、确认、提报、回填。
2. 复提批次：没有新源表时，从最近提报情况整理表中识别失败或可复提 SKU。
3. 查价重跑：同一批次再次整合查价结果时，更新当前筛品查价表并备份旧表。
4. 业务确认：运营复制 ERP 文本发给业务，收到确认表后生成提报文件。
5. 安全提报：先演练或只上传，再在明确确认后真实提交。
6. 审核回填：导出审核/提报情况，整理状态并回填最终结果，作为下一批依据。

## 5. 业务流程

### 5.1 总流程

```text
准备任务
  → 筛品查价
  → 业务确认
  → 后台提报
  → 审核回填
  → 下一批复提依据
```

### 5.2 阶段说明

| 阶段 | 用户动作 | 工具动作 | 关键产物 |
| --- | --- | --- | --- |
| 准备任务 | 确认批次、环境、源表 | 读取配置、识别工作区、校验目录 | 批次清单、配置状态 |
| 筛品查价 | 启动筛品查价链路 | 筛品、拆 SKU、后台查价、邮件下载、查价整合、计算新人价 | 筛品查价表、查价失败 SKU、ERP 文本 |
| 业务确认 | 发送 ERP 文本并接收确认表 | 根据确认结果生成提报文件 | 业务已确认表、提报 PART 文件 |
| 后台提报 | 选择演练、上传或真实提交 | 按 PART 文件上传并提交，保留二次确认 | 提报过程日志、提交结果 |
| 审核回填 | 导出审核结果并下载 | 整理提报状态，回填最终结果 | 提报情况整理表、复提依据 |

## 7. 信息架构

### 7.1 Streamlit GUI MVP

单页布局：

1. 批次概览。
2. 流程阶段看板。
3. 关键文件结果。
4. 最少操作按钮。
5. 产品说明。

### 7.2 React 工作台 MVP

单页工作台：

1. 顶部批次与阶段摘要。
2. 左侧/中间流程阶段卡片。
3. 关键文件卡片。
4. 品池概览与失败原因。
5. 最近日志和低风险入口。

### 7.3 命令行入口

主菜单保留完整流程：

```text
1 筛品
2 提取并拆分查价前SKU
3 一键执行本地流程（筛品+拆分）
4 后台查价上传并导出到邮箱
5 Outlook邮件下载查价结果
6 查看当前配置
7 查价结果整合并生成新人价
8 提报/审核整理
9 新人价工作流向导
0 退出
```

## 8. 数据与文件模型

### 8.1 核心配置

| 字段 | 含义 |
| --- | --- |
| `batch_name` | 当前批次名 |
| `batch_date` | 批次日期，可为空时自动推断 |
| `source_file` / `source_auto_dir` | 源表文件或自动检测目录 |
| `output_root` | 输出根目录 |
| `registration_input_dir` | 业务确认表输入目录 |
| `registration_submit_dir` | 提报文件输出目录 |
| `log_root` | 日志目录 |

### 8.2 关键产物

| 产物 | 命名/目录 | 用途 |
| --- | --- | --- |
| 筛品查价表 | `{batch_name}_筛品查价表{查价日期}.xlsx` | 主结果表，包含候选 SKU、查价和新人价 |

| 疑似误下载目录 | `data/output/查价结果导出/疑似误下载/` | 隔离非查价结果文件 |

## 9. 接口需求

### 9.1 当前只读 API

| 接口 | 方法 | 用途 | 风险 |
| --- | --- | --- | --- |
| `/api/health` | GET | 健康检查 | 低 |
| `/api/dashboard` | GET | 读取批次看板上下文、阶段、文件、日志 | 低 |
| `/api/open-path` | POST | 打开本地文件或目录 | 低 |
| `/api/start-cli` | POST | 启动现有命令行工具 | 中，仍需用户在 CLI 内确认 |

### 9.2 V1.2 服务化接口方向

| 能力 | 说明 |
| --- | --- |
| 任务创建 | 为筛品、查价、提报等动作创建任务实例 |
| 任务状态 | 返回 pending/running/success/failed/need_user |
| 日志流 | 按任务返回结构化日志和最近异常 |
| 文件索引 | 返回批次相关文件状态、更新时间、打开路径 |
| 风险确认 | 对真实提报等高风险任务要求二次确认和审计记录 |

## 10. 安全与风控

### 10.1 高风险动作

- 真实后台提报。
- 后台审核/提报情况导出。
- 自动发送业务邮件。
- 修改配置和业务规则。

### 10.2 当前控制策略

- GUI MVP 不提供真实提报按钮。
- 命令行真实提交需要明确选择和输入确认口令。
- 支持 `dry_run` 和 `upload_only` 分层执行。
- 重跑时归档旧文件，避免历史文件误参与。
- 疑似误下载文件隔离到独立目录。
- 测试环境写入 `test_workspace`，不污染正式目录。

## 11. 成功指标

### 11.1 MVP Demo 指标

- 1 分钟内讲清楚业务痛点、页面结构和范围取舍。
- 页面能展示批次概览、5 阶段、关键文件和日志入口。
- 评审者能理解为什么不把真实提报放进首版 GUI。

### 11.2 业务指标

- 单批次人工操作时长。
- 查找关键文件耗时。
- 查价结果误整合次数。
- 历史提报文件误上传次数。
- 提报失败原因可归类比例。
- 可复提 SKU 识别数量。

## 12. 验收标准

### 12.1 GUI MVP 验收

- 双击 `run_gui.bat` 能打开页面。
- 页面标题为“新人价自动化批次看板”。
- 页面展示批次名、环境、批次日期、输出目录、日志目录、批次清单状态、下一步建议。
- 页面固定展示准备任务、筛品查价、业务确认、后台提报、审核回填。
- 页面展示关键文件或目录状态。
- 页面文案面向运营，避免直接堆技术字段名。
- 页面包含产品说明：当前版本以批次看板为核心，完整流程执行仍通过现有命令行工具完成。

### 12.2 React 工作台验收

- 双击 `run_workbench.bat` 能启动 API 和前端。
- API 健康检查可访问。
- 前端能读取 `/api/dashboard` 并展示批次数据。
- 前端失败时能提示 API 连接失败，而不是白屏。

### 12.3 CLI 主流程验收

- `run.bat` 和 `run_test.bat` 原有入口不受 GUI 影响。
- 工作流向导可按阶段继续执行。
- 高风险动作仍保留人工确认。

## 14. 发布与演示计划

### 14.1 Demo 前检查

1. 确认当前分支为 `feature/gui-mvp-demo`。
2. 确认 `config.yaml` 或 `config.test.yaml` 指向可演示目录。
3. 确认 Streamlit 或 React 工作台依赖可用。
4. 确认输出目录中存在示例批次产物。
5. 先用测试环境演练，不触发真实提报。

### 14.2 演示顺序

1. 打开 README 或 Vision，说明项目目标。
2. 双击 `run_gui.bat` 或 `run_workbench.bat`。
3. 展示批次概览和阶段看板。
4. 打开关键文件或日志目录。
5. 切到命令行入口，说明完整流程仍在原工具中执行。
6. 用 Case Study 总结 MVP 取舍和下一步路线。
