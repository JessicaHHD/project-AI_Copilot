# 新人价自动化工具

更新时间：2026-08-01  
项目阶段：本地测试链路基本跑通，进入“工作流向导 + 命名/文件管理 + 复提闭环”完善阶段。

## 1. 项目目标

新人价自动化工具用于减少运营在新人价提报流程中的重复操作，覆盖：

- 大盘订单源表筛品
- 查价 SKU 拆分
- 后台查价上传与导出
- Outlook 邮件下载查价结果
- 查价结果整合与新人价计算
- 业务确认表生成提报 SKU 文件
- 后台新人价补贴报名
- 后台审核/提报情况导出
- 提报情况整理并回填最终结果
- 后续批次复提候选识别

工具定位是“半自动工作流”：规则明确、重复性的处理交给工具；业务确认、真实提报、审核导出等关键风险动作保留人工确认。

## 2. 启动方式

### 正式目录

双击：

```
run.bat
```

正式配置文件：

```
config.yaml
```

### 隔离测试目录

双击：

```
run_test.bat
```

测试配置文件：

```
config.test.yaml
```

测试模式下，输入、输出、日志、浏览器缓存都会写入：

```
test_workspace/
```

不会干扰正式目录的文件。`run.bat` 和 `run_test.bat` 启动前会清理 Python 脚本缓存，避免旧代码残留。

## 6. 标准业务流程

### 阶段 1：筛品查价整合

人工：

- 初次提报时，从后台/取数中心下载大盘订单源表。
- 复提时，如果没有新大盘源表，可以直接使用最近提报整理表中的复提候选。

工具：

- 自动检测是否有新增大盘源表。
- 有新源表：执行筛品、拆分、后台查价、Outlook 下载、最终整合。
- 无新源表：从最近提报整理表提取“提报失败 + 可复提成功”SKU，再走查价和整合。

输出：

```
{batch_name}_筛品查价表{查价日期}.xlsx
```

同一批次再次执行“查价结果整合并生成新人价”时，工具会优先更新当前这张筛品查价表，不再每次生成一张新的最终表。更新前会先把旧文件备份到 `最终结果/_archive/`，主 sheet `筛选结果` 会保留历史查价字段，并新增/更新本次 `{查价日期}_查价` 和 `新人价`。

查价结果整合会优先使用批次清单里记录的“本次 Outlook 下载文件”，避免把 `查价结果导出` 目录里的历史文件一起合并。如果发现下载到的文件像“提报/审核情况导出表”而不是查价结果，会移动到 `查价结果导出/疑似误下载/`，本次不参与新人价计算。

暂停点：人工迁移线上表、给业务/采销发邮件确认。

### 阶段 2：业务确认

人工：

- 将筛品查价表迁移到线上表。
- 使用 ERP 汇总文本编辑邮件。
- 收到业务确认后，整理业务确认表。

业务确认表推荐命名：

```
{batch_name}_业务已确认表_{YYYYMMDD}.xlsx
```

工具：

- 读取业务确认表。
- 将业务确认结果标准化为 `业务是否参与报名`：`参与报名` / `不报名` / `未确认`。
- 直接更新当前最新的筛品查价最终表：主 sheet `筛选结果` 只新增/更新 `业务是否参与报名`。
- 原始确认字段、原始值和判断说明写入 `业务确认明细` sheet，不堆到主表。
- 生成提报汇总文件和 PART 文件；PART 文件仍只包含 `skuid`、`促销价`，避免影响后台上传。
- 重新生成提报文件前，同批次旧提报文件会归档到 `_archive`，不会参与本次后台上传。

输出：

```
当前最新筛品查价表：新增/更新 业务是否参与报名 + 业务确认明细
{batch_name}_提报sku_{YYYYMMDD}.xlsx
{batch_name}_提报sku_{YYYYMMDD}_PART01.xlsx
{batch_name}_提报sku_{YYYYMMDD}_PART02.xlsx
```

### 阶段 3：后台提报

工具支持三种模式：

- `dry_run`：只演练到上传页，不上传、不提交。
- `upload_only`：选择文件上传到页面，但不点击提交。
- `submit`：真实上传并点击提交，必须输入 `确认提报`。

安全限制：

- 默认推荐只跑 1 个文件。
- 全量提报需要输入 `全量提报`。
- 真实提交必须输入 `确认提报`。
- 找不到明确按钮时停止并保存截图/HTML，不做模糊提交。

### 阶段 4：审核结果导出与整理

工具：

- 进入新人价已报名页面。
- 选择当前月份计划，点击查看。
- 点击下载，等待 Outlook 中“增长权益”邮件。
- 下载审核/提报情况 Excel。
- 整理状态并回填最终结果。
- 保留阶段 2 已写入的 `业务是否参与报名`，用于后续复提排除。
- 保留或重建 `业务确认明细` sheet，不把原始确认字段堆到主表。
- 如果后台导出中存在不在本轮主表的 SKU，会标记为 `后台额外提报SKU` 并追加到整理后的 `筛选结果`，失败时可进入后续复提闭环。
- 额外 SKU 会同步输出到 `非本轮主表提报记录` sheet，便于单独核查。

输出：

```
{batch_name}_提报情况整理表{审核导出文件名}_{YYYYMMDD}.xlsx
```

该文件就是后续批次持续维护和复提判断的状态表。

## 7. 关键规则

### 筛品/复提规则

- 未检测到最终结果中的提报状态字段时，按初次提报处理。
- 最近提报整理表中 `提报状态_最终 = 提报失败` 的 SKU，进入复提候选。
- `提报状态_最终 = 提报成功` 且标签/详情包含 `转化不满足` 或 `删促`，进入复提候选。
- 普通成功 SKU 视为已在新人价品池，有新源表时会剔除。
- 整理表中 `业务是否参与报名 = 不报名` 的 SKU，会在后续复提中剔除，避免业务明确不参加仍被误报。

### 复提二次查价价格复核

- 复提 SKU 重新查价后，会和上一轮提报整理表中的最近一次查价价格对比。
- 两次查价差异超过配置阈值时，本轮暂不提报该 SKU，不进入主 sheet `筛选结果`。
- 被拦下的 SKU 会写入 `价格复核剔除` sheet，供运营人工确认。
- 所有参与复核的复提 SKU 会写入 `价格复核明细` sheet，方便追溯上次查价、本次查价和差异原因。
- 本轮再次提报完成后，仍通过“提报/审核情况整理”生成新的提报情况整理表，记录本轮实际提报成功/失败状态。

### 新人价计算规则

- 自营：查价价格 - 8
- 非自营：查价价格 - 6.5
- 结果小于等于 0 时填 0.01
- 新人价大于等于 200 的商品剔除

当前后台查价导出字段变化后，价格字段优先使用：

```
价格
```

并兼容旧字段：

```
100天最低价
100天最低价格
```

### 提报情况归并规则

- 同 SKU 多条记录时，成功优先。
- 任一记录成功，则最终为 `提报成功`。
- 详情包含 `严重错误` 时标记为 `重复提报`，并视为历史已成功。
- 若没有成功记录，则取最新失败记录。
- 未在提报情况表出现的 SKU 标记为 `未提报/未匹配`。

失败标签规则：

- `交叉时间内已存在` → `叠加促销过多`
- `严重错误` → `重复提报`
- `不满足促销价低于100天最低价` → `不满足促销价低于100天最低价`
- `近30天日均拉新量` → `日均拉新不满足`
- `不符合30天转化用户数` → `30天转化不满足`
- 其他失败 → 保留原详情作为标签

## 8. 文件命名规则

当前统一围绕 `batch_name` 命名，例如 `8月第1批提报`。

| 文件 | 命名规则 |
| --- | --- |
| 筛品查价表 | `{batch_name}_筛品查价表{查价日期}.xlsx` |
| 业务确认表 | `{batch_name}_业务已确认表_{YYYYMMDD}.xlsx` |
| 提报 SKU 文件 | `{batch_name}_提报sku_{YYYYMMDD}_PART01.xlsx` |
| 提报情况整理表 | `{batch_name}_提报情况整理表{审核导出文件名}_{YYYYMMDD}.xlsx` |
| 批次清单 | `data/output/批次清单/{batch_name}_{YYYYMMDD}.json` |

多数最终输出同名文件不覆盖，会自动追加 `_2`、`_3`。筛品查价表比较特殊：同一批次再次执行查价结果整合时，会更新当前筛品查价表，并在 `最终结果/_archive/` 留更新前备份。查价前 SKU PART、查价结果下载文件和提报 PART 会在重新生成/下载前先归档同批次旧文件，避免历史文件被误上传或误整合。

## 9. 目录说明

### 正式目录

```

data/output/查价前sku/          查价前 SKU PART 文件
data/output/查价前sku/_archive/ 历史查价前 SKU 文件归档，不自动上传
data/output/查价结果导出/       Outlook 下载的查价结果
data/output/查价结果导出/疑似误下载/ 被识别为非查价结果的误下载文件
data/output/最终结果/           筛品查价表、提报情况整理表
data/output/最终结果/_archive/  筛品查价表更新前备份
data/output/提报文件/           提报 SKU PART 文件
data/output/提报文件/_archive/  历史提报文件归档，不自动上传
data/output/提报情况导出/       后台审核/提报情况导出表
data/output/批次清单/           工作流向导批次清单
logs/                           自动化日志和调试截图
browser_profiles/               浏览器登录缓存
```

### 历史 PART 文件防误传

- 每次重新拆分查价前 SKU，会先把同批次旧查价汇总和 PART 文件归档到 `查价前sku/_archive/`。
- 每次 Outlook 下载查价结果前，会先把旧查价结果 Excel 归档到 `查价结果导出/_archive/`。
- 每次重新生成提报文件，会先把同批次旧提报汇总和 PART 文件归档到 `提报文件/_archive/`。
- 后台查价上传和后台提报上传会优先读取批次清单中的“本次生成 PART 文件”，不会只靠目录通配符扫历史文件。
- 查价结果整合会优先读取批次清单中的“本次查价结果文件”，不会把历史查价结果或误下载的提报情况表一起合并。
- 如果批次清单缺失，工具才会回退到目录匹配，并在菜单中提示历史文件风险。

## 10. 常用配置

主要配置在 `config.yaml`，测试配置在 `config.test.yaml`。

常用项：

- `batch_name`：当前批次名称。
- `batch_date`：批次日期，空则默认当天。
- `source_auto_detect`：是否自动检测大盘订单源表。
- `source_auto_dir`：大盘订单源表自动检测目录。
- `source_auto_patterns`：源表文件名匹配规则。
- `filter_round_mode`：筛品模式，默认 `auto`。
- `resubmit_final_file`：指定提报整理表，空则自动取最新。
- `resubmit_price_review_enabled`：是否启用复提二次查价价格复核。
- `resubmit_price_diff_abs_threshold`：复提查价差值阈值，默认 `10` 元。
- `resubmit_price_diff_rate_threshold`：复提查价差异比例阈值，默认 `0.2`。
- `final_price_value_column`：当前为 `价格`。
- `registration_month_threshold_day`：月份计划判断阈值，默认 25 号及以后优先下月计划。

## 11. 人工边界

当前不自动化的部分：

1. 初次提报的大盘订单源表下载。
2. 将筛品查价表迁移到线上表。

4. 业务确认表的人工回收与确认。
5. 真实提报前的风险判断。
6. 是否导出审核结果的人工选择。
