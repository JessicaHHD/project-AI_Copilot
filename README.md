# 新人价智能运营 Copilot MVP

> 一个基于 Vibe coding 搭建的新人价运营 Workflow Automation Demo。  
> 目标是把新人价运营中的筛品、查价、提报、审核回填和失败 SKU 返工流程，沉淀为可追踪、可暂停、可复盘的半自动工作流。

## 1. 项目当前状态

当前版本为本地 MVP，已完成核心自动化链路和批次看板原型：

- CLI 工作流：覆盖筛品、查价、业务确认、后台提报、审核回填、复提判断。
- 失败 SKU 返工流程：支持从后台导出的失败 SKU 表中提取 SKU，重新查价、价格复核并生成重新提报文件。
- 批次文件管理：按批次记录关键产物，包括查价前 SKU、查价结果、提报文件、审核整理表和日志。
- GUI MVP / React 工作台原型：展示批次状态、流程阶段、关键文件和日志入口。
- 安全边界：真实提报、后台导出等高风险动作保留人工确认，不做黑盒全自动执行。

## 2. 目前  MVP 功能范围

### 2.1 主工作流

当前主流程覆盖新人价提报的核心链路：

1. 大盘源表筛品
2. 查价 SKU 提取与拆分
3. 后台查价上传与导出
4. Outlook 查价结果下载
5. 查价结果整合与新人价计算
6. 业务确认后生成提报文件
7. 后台提报
8. 审核 / 提报情况导出
9. 提报结果整理与复提候选识别

### 2.2 失败 SKU 返工流程

最新迭代新增了独立的失败 SKU 返工流程，不改变原有主流程：

```text
后台失败 SKU 表
→ 提取失败 SKU
→ 去重拆分
→ 后台重新查价
→ Outlook 下载查价结果
→ 计算本次新人价
→ 与历史新人价做价格复核
→ 生成重新提报文件

## 3. 产品设计原则
- 不替代人工决策：业务确认、真实提报等关键动作保留人工判断。
- 高风险动作强确认：真实提交前需要明确确认，默认推荐 dry-run。
- 不破坏原流程：失败 SKU 返工采用旁路流程，不改主链路。
- 批次可追踪：关键文件、日志和结果按批次沉淀。
- 先自动化，再智能化：优先解决重复执行问题，再逐步引入 AI 分析和决策辅助。

## 4. 技术实现
- Python：核心 Workflow Automation
- openpyxl：Excel 读取、清洗、拆分和结果生成
- Playwright：后台页面自动化
- Outlook 自动化：查价结果邮件下载
- Streamlit / React：批次看板与工作台原型
- 本地文件系统：批次产物与日志管理

## 6. 当前局限与下一步
当前版本仍是本地 MVP，重点验证 workflow 设计和业务闭环：
- GUI 主要展示状态，不直接执行高风险操作。
- 后台自动化依赖页面结构，仍需人工监督。
- 数据分析能力仍以规则和表格处理为主，AI 辅助决策尚在规划阶段。
下一步计划：
- 完善任务状态看板
- 建设文件与日志中心
- 接入更多历史批次数据
- 支持复提优先级和掉池预警
- 将只读接口抽象为服务化接口
- 探索 AI Copilot 自然语言查询与运营建议
